In **Java**, constructors are mainly discussed in these forms:

### 1. Default Constructor

A **default constructor is automatically provided by the compiler only when you don't write any constructor**. ([Oracle Docs](https://docs.oracle.com/javase/tutorial/java/javaOO/constructors.html?utm_source=chatgpt.com "Providing Constructors for Your Classes (The Java™ Tutorials > Learning the Java Language > Classes and Objects)"))

```java
class Student {
    int age;
    String name;
}
```

Java effectively provides:

```java
Student() {
    super();
}
```

Then:

```java
Student s = new Student();
```

---

### 2. No-Argument Constructor

A constructor that you **write yourself** and which takes no parameters.

```java
class Student {

    Student() {
        System.out.println("Student created");
    }
}
```

```java
Student s = new Student();
```

**Important interview point:**  
**Default constructor ≠ always the same as no-argument constructor.**

- **Default constructor** → compiler-generated when you provide **no constructor**.
    
- **No-arg constructor** → any constructor having **zero parameters**, whether written by you or generated by the compiler. ([Oracle Docs](https://docs.oracle.com/javase/tutorial/java/javaOO/constructors.html?utm_source=chatgpt.com "Providing Constructors for Your Classes (The Java™ Tutorials > Learning the Java Language > Classes and Objects)"))
    

---

### 3. Parameterized Constructor

A constructor that accepts parameters.

```java
class Student {
    String name;
    int age;

    Student(String name, int age) {
        this.name = name;
        this.age = age;
    }
}
```

Usage:

```java
Student s = new Student("Pavan", 22);
```

This allows each object to be initialized with different values. ([Oracle Docs](https://docs.oracle.com/javase/tutorial/java/javaOO/constructors.html?utm_source=chatgpt.com "Providing Constructors for Your Classes (The Java™ Tutorials > Learning the Java Language > Classes and Objects)"))

---

### 4. Constructor Overloading

You can have multiple constructors with **different parameter lists**.

```java
class Student {

    Student() {
        System.out.println("No args");
    }

    Student(String name) {
        System.out.println(name);
    }

    Student(String name, int age) {
        System.out.println(name + " " + age);
    }
}
```

```java
new Student();
new Student("Pavan");
new Student("Pavan", 22);
```

This is called **constructor overloading**. ([Oracle Docs](https://docs.oracle.com/javase/specs/jls/se7/html/jls-8.html?utm_source=chatgpt.com "Chapter 8. Classes"))

### Interview summary

|Type|Parameters|Who provides it?|
|---|--:|---|
|Default constructor|0|Compiler, if no constructor exists|
|No-arg constructor|0|Programmer or compiler|
|Parameterized constructor|1+|Programmer|
|Overloaded constructors|Different lists|Programmer|

**Most important interview question:**

> If I create a parameterized constructor, will Java still provide a default constructor?

**Answer: No.** Once you declare any constructor, the compiler does not automatically provide the default constructor. ([Oracle Docs](https://docs.oracle.com/javase/tutorial/java/javaOO/constructors.html?utm_source=chatgpt.com "Providing Constructors for Your Classes (The Java™ Tutorials > Learning the Java Language > Classes and Objects)"))

# Java Constructor Interview Questions

Constructors are a **very common Java interview topic**, especially for fresher/junior Java and Spring Boot interviews.

## 1. What is a constructor?

A constructor is a special member of a class used to **initialize an object**.

```java
class Student {
    String name;

    Student() {
        name = "Pavan";
    }
}
```

When you write:

```java
Student s = new Student();
```

the constructor is called automatically.

### Key points

- Constructor name must be the **same as the class name**.
    
- It has **no return type**, not even `void`.
    
- It is called automatically when an object is created.
    
- Constructors can be **overloaded**.
    
- Constructors are **not inherited**.
    

---

# 2. Constructor vs Method

|Constructor|Method|
|---|---|
|Initializes an object|Performs an operation|
|Same name as class|Can have any valid name|
|No return type|Has return type or `void`|
|Called during object creation|Called explicitly|
|Cannot be inherited|Methods can be inherited|
|Can be overloaded|Can be overloaded|
|Cannot be overridden|Can be overridden|

---

# 3. What happens if you don't create a constructor?

Java provides a **default constructor automatically** only if you don't declare any constructor.

```java
class Student {
    String name;
}
```

Compiler conceptually provides:

```java
Student() {
    super();
}
```

So:

```java
Student s = new Student();
```

works.

### Interview trap

If you create **any constructor**, Java no longer provides the automatic no-argument constructor.

```java
class Student {
    Student(String name) {
    }
}
```

This will fail:

```java
Student s = new Student(); // ❌
```

---

# 4. What is a default constructor?

A default constructor is the **compiler-provided no-argument constructor** when the class has no constructor declared.

```java
class A {
}
```

Compiler provides approximately:

```java
A() {
    super();
}
```

Don't confuse this with a **user-defined no-argument constructor**:

```java
class A {
    A() {
        System.out.println("Hello");
    }
}
```

This is a no-argument constructor, but it is **not compiler-provided**.

---

# 5. Can constructors be overloaded?

**Yes.**

```java
class Student {

    Student() {
    }

    Student(String name) {
    }

    Student(String name, int age) {
    }
}
```

This is constructor overloading.

The compiler determines which constructor to call based on the arguments.

```java
new Student();
new Student("Pavan");
new Student("Pavan", 22);
```

---

# 6. Can constructors be overridden?

**No.**

Constructors are not inherited, so they cannot be overridden.

```java
class Parent {
    Parent() {}
}

class Child extends Parent {
    Child() {}
}
```

`Child()` is **not overriding** `Parent()`.

It is a separate constructor.

---

# 7. Can a constructor be private?

**Yes.**

```java
class Database {

    private Database() {
    }
}
```

This prevents outside classes from directly creating objects.

Common use case:

**Singleton pattern**

```java
class Singleton {

    private static Singleton instance;

    private Singleton() {
    }

    public static Singleton getInstance() {
        if (instance == null) {
            instance = new Singleton();
        }
        return instance;
    }
}
```

---

# 8. Can a constructor be `static`?

**No.**

```java
class Test {
    static Test() { } // ❌
}
```

Why?

`static` belongs to the class, while constructors are associated with **object initialization**.

---

# 9. Can a constructor be `final`?

**No.**

```java
class Test {
    final Test() { } // ❌
}
```

`final` prevents overriding, but constructors cannot be overridden anyway.

---

# 10. Can a constructor be abstract?

**No.**

```java
abstract Test() { } // ❌
```

An abstract method has to be implemented by subclasses. Constructors aren't inherited or overridden.

An **abstract class can have constructors**, however:

```java
abstract class Animal {

    Animal() {
        System.out.println("Animal constructor");
    }
}
```

---

# 11. Can an abstract class have a constructor?

**Yes.**

```java
abstract class Animal {

    Animal() {
        System.out.println("Animal constructor");
    }
}

class Dog extends Animal {

    Dog() {
        System.out.println("Dog constructor");
    }
}
```

```java
Dog d = new Dog();
```

Output:

```text
Animal constructor
Dog constructor
```

This happens because the child constructor must initialize the parent part of the object.

---

# 12. What is constructor chaining?

Calling one constructor from another constructor is called **constructor chaining**.

Use `this()`:

```java
class Student {

    Student() {
        this("Unknown");
    }

    Student(String name) {
        System.out.println(name);
    }
}
```

```java
new Student();
```

Output:

```text
Unknown
```

---

# 13. What is `this()` in a constructor?

`this()` calls **another constructor of the same class**.

```java
class Student {

    Student() {
        this("Pavan");
    }

    Student(String name) {
        System.out.println(name);
    }
}
```

Important:

```java
this();
```

or

```java
this("Pavan");
```

must be the **first statement** in the constructor.

This is invalid:

```java
Student() {
    System.out.println("Hello");
    this("Pavan"); // ❌
}
```

---

# 14. What is `super()` in a constructor?

`super()` calls the **parent class constructor**.

```java
class Animal {

    Animal() {
        System.out.println("Animal");
    }
}

class Dog extends Animal {

    Dog() {
        super();
        System.out.println("Dog");
    }
}
```

Output:

```text
Animal
Dog
```

If you don't explicitly write `super()`, Java inserts it automatically **if the parent has an accessible no-argument constructor**.

---

# 15. `this()` vs `super()`

|`this()`|`super()`|
|---|---|
|Calls same-class constructor|Calls parent-class constructor|
|Used for constructor chaining|Used for parent initialization|
|Must be first statement|Must be first statement|
|Cannot use both in same constructor|Cannot use both in same constructor|

For example:

```java
class Child extends Parent {

    Child() {
        this(10);
    }

    Child(int x) {
        super();
    }
}
```

This is valid because `this()` and `super()` are in **different constructors**.

---

# 16. What is the order of constructor execution?

Consider:

```java
class Parent {

    Parent() {
        System.out.println("Parent");
    }
}

class Child extends Parent {

    Child() {
        System.out.println("Child");
    }
}
```

```java
new Child();
```

Output:

```text
Parent
Child
```

The general order is:

```text
Object constructor
      ↓
Parent constructor
      ↓
Child constructor
```

---

# 17. What happens if parent has no default constructor?

Example:

```java
class Parent {

    Parent(String name) {
    }
}

class Child extends Parent {

    Child() {
    }
}
```

❌ Compilation error.

Why?

The compiler tries to insert:

```java
super();
```

But `Parent` doesn't have a no-argument constructor.

Fix:

```java
class Child extends Parent {

    Child() {
        super("Pavan");
    }
}
```

---

# 18. Can constructor call another constructor using `this()` and `super()` together?

**No, not in the same constructor.**

This is invalid:

```java
Child() {
    this(10);
    super(); // ❌
}
```

Both must be the first statement, so they cannot coexist in one constructor.

---

# 19. Can a constructor call a method?

**Yes.**

```java
class Test {

    Test() {
        display();
    }

    void display() {
        System.out.println("Hello");
    }
}
```

But there is an important interview warning:

> Avoid calling overridable methods from constructors.

Example:

```java
class Parent {

    Parent() {
        display();
    }

    void display() {
        System.out.println("Parent");
    }
}

class Child extends Parent {

    int x = 10;

    @Override
    void display() {
        System.out.println(x);
    }
}
```

During parent construction, child fields may not yet be initialized as expected.

---

# 20. Can constructor throw an exception?

**Yes.**

```java
class Test {

    Test() throws Exception {
        // ...
    }
}
```

You can also throw an exception:

```java
class Student {

    Student(int age) {
        if (age < 0) {
            throw new IllegalArgumentException("Invalid age");
        }
    }
}
```

---

# 21. Can constructor be synchronized?

No, constructors cannot be declared `synchronized`.

```java
synchronized Test() { } // ❌
```

You can synchronize methods or blocks, but not constructors.

---

# 22. Can constructor be native?

Constructors cannot be declared `native`.

```java
native Test(); // ❌
```

---

# 23. Can a constructor return a value?

No.

```java
class Test {

    Test() {
        return; // ✅ allowed
    }
}
```

A constructor can use a bare `return;` to exit, but cannot return a value:

```java
Test() {
    return 10; // ❌
}
```

---

# 24. Can we create an object without calling a constructor?

This is a more advanced interview question.

With normal:

```java
new Student();
```

a constructor is involved.

But Java has mechanisms such as **deserialization** where an object can be instantiated without invoking the class's normal constructor in the usual way.

For fresher interviews, remember:

> Normal object creation using `new` invokes a constructor.

---

# 25. Constructor and inheritance

Constructors are **not inherited**.

```java
class Parent {
    Parent() {}
}

class Child extends Parent {
}
```

`Child` does not inherit `Parent()`.

Instead, the `Child` constructor invokes the parent constructor using `super()`.

---

# 26. Constructor and polymorphism

Constructors don't participate in runtime polymorphism.

```java
Parent p = new Child();
```

The object uses the `Child` constructor during creation, but constructors themselves are not dynamically dispatched like overridden methods.

---

# 27. Tricky output question

What is the output?

```java
class A {

    A() {
        this(10);
        System.out.println("A()");
    }

    A(int x) {
        System.out.println("A(int)");
    }
}

public class Main {
    public static void main(String[] args) {
        new A();
    }
}
```

### Answer

```text
A(int)
A()
```

Because:

```java
A()
 ↓
this(10)
 ↓
A(int)
 ↓
back to A()
```

---

# 28. Very common interview question

### What happens here?

```java
class A {

    A() {
        this(10);
    }

    A(int x) {
        this();
    }
}
```

This causes **constructor recursion**.

```text
A()
 ↓
A(int)
 ↓
A()
 ↓
A(int)
 ...
```

Eventually you get:

```text
StackOverflowError
```

---

# 29. Constructor initialization order — important

Consider:

```java
class Parent {

    int a = 10;

    Parent() {
        System.out.println("Parent constructor");
    }
}

class Child extends Parent {

    int b = 20;

    Child() {
        System.out.println("Child constructor");
    }
}
```

When:

```java
new Child();
```

the initialization broadly happens:

```text
1. Memory allocated
2. Object fields receive default values
3. Parent initialization
   ├── parent instance field initializers
   └── parent constructor
4. Child initialization
   ├── child instance field initializers
   └── child constructor
```

This order is **very important for output-based interview questions**.

`Child` does not inherit `Parent()`.

Instead, the `Child` constructor invokes the parent constructor using `super()`.

---

# 26. Constructor and polymorphism

Constructors don't participate in runtime polymorphism.

```java
Parent p = new Child();
```

The object uses the `Child` constructor during creation, but constructors themselves are not dynamically dispatched like overridden methods.

# 27. Tricky output question

What is the output?

```java
class A {

    A() {
        this(10);
        System.out.println("A()");
    }

    A(int x) {
        System.out.println("A(int)");
    }
}

public class Main {
    public static void main(String[] args) {
        new A();
    }
}
```

### Answer

```text
A(int)
A()
```

Because:

```java
A()
 ↓
this(10)
 ↓
A(int)
 ↓
back to A()
```

# 28. Very common interview question

### What happens here?

```java
class A {

    A() {
        this(10);
    }

    A(int x) {
        this();
    }
}
```

This causes **constructor recursion**.

```text
A()
 ↓
A(int)
 ↓
A()
 ↓
A(int)
 ...
```

Eventually you get:

```text
StackOverflowError
```

# 29. Constructor initialization order — important

Consider:

```java
class Parent {

    int a = 10;

    Parent() {
        System.out.println("Parent constructor");
    }
}

class Child extends Parent {

    int b = 20;

    Child() {
        System.out.println("Child constructor");
    }
}
```

When:

```java
new Child();
```

the initialization broadly happens:

```text
1. Memory allocated
2. Object fields receive default values
3. Parent initialization
   ├── parent instance field initializers
   └── parent constructor
4. Child initialization
   ├── child instance field initializers
   └── child constructor
```

This order is **very important for output-based interview questions**.
